### 2.1 全量数据实测（50 万用户 / 300 万行为 / 52 万订单 / 100 万曝光）

| 发现 | 处理 |
| --- | --- |
| 6 张业务对象原为视图，每次查询对 300 万行明细做 `COUNT(DISTINCT ...)`，单次查询需 30-300s，超过 `SQL_TIMEOUT_SECONDS=30`，由超时保护正确拦截（`timeout` + `surface_to_user`） | 新增 `scripts/materialize_marts.py`：把同名对象改写为带粒度主键的物理表，名称/字段/口径/授权/契约完全不变；物化后单表查询 ≤ 0.11s |
| 物化后 10 个正向用例全部通过，`Q05 复购用户` 返回真实行数（样例数据下为 0 行，属于数据规模差异，不是逻辑缺陷） | 报告 `reports/acceptance_*_full.md` |
| 全量重导后必须重新物化 | `load_full_data.py` 与 `materialize_marts.py` 的文档与 README 已说明 |

验收端到端标准（文档 8.4）逐条对应：

1. 正向用例全部 `status="success"` → 见报告第 1 节；
2. 负向用例不执行危险 SQL → 见报告第 2 节（N01-N08）与 `tests/test_acceptance.py`；
3. 结果包含 `result_columns`/`result_rows`/`row_count` → `test_positive_case` 断言；
4. 生成的 SQL 只引用 V1 业务表 → `acceptance.assert_safe_sql()` + 校验器白名单；
5. Catalog 未命中不允许猜表 → `test_schema_linking_errors_when_nothing_matches`、N03/N07；
6. 重试次数不超过 `SQL_MAX_RETRIES` → `test_r01`/`test_r05`/图集成用例；
7. 数据库密码与连接信息不进入日志或 State → `settings.redact()`、`test_e2e_criteria_secrets_never_appear_in_state`；
8. 关键节点均有单元测试 + 完整图集成测试 → `tests/test_nodes.py`、`tests/test_graph.py`；
9. sample 与 full 数据共用 schema/Catalog/节点契约 → `test_e2e_criteria_sample_and_full_share_the_same_contract`；
10. 修改 Catalog 版本后必须重跑用例 → `test_catalog_version_mismatch_is_rejected` + 统一用例入口。

## 3. 关键口径决策（文档允许范围内的确定性选择）

| # | 决策 | 依据 |
| --- | --- | --- |
| 1 | `validate_sql` 只改写 `LIMIT`（补 100 / 截断到 100），可用 `SQL_LIMIT_POLICY=reject` 切换成拒绝 | 文档 5.6 第 8、9 条 |
| 2 | 可恢复执行错误写 `status="pending"`+`error`，终止性错误写 `status="failed"`；失败出口统一兜底 | 文档 5.7 + 5.10 路由函数读取 `recovery_strategy` |
| 3 | 超时重试 1 次后 `surface_to_user`；其他可恢复错误用满 2 次后 `retry_exhausted` | 文档 8.3 R03 / R05 |
| 4 | 破坏性请求在调用 LLM 之前规则拦截（`unsafe_request` + `abort`） | 文档 8.2 N01“直接拒绝” |
| 5 | 用户粒度查询以 `dim_user` 为 JOIN 锚点，并作为锚点候选写入 `candidate_tables` | 文档 2.3 示例、5.4“selected ⊆ candidate” |
| 6 | 比率指标登记分子/分母字段，“点击后转化率”= `converted_count/clicked_count` | 文档 6.3.3、8.2 N04 |
| 7 | 关键词若**精确**命中字段名/同义词（如“复购用户”）则参与选表约束 | 文档 5.4 覆盖度要求 + 实测真实模型行为 |
| 8 | 过滤条件解析允许命中 `flag` 字段，且按匹配长度优先（避免“用户”误命中 `user_id`） | 文档 5.4/6.3.2 |
| 9 | 无 Key 或 `--offline` 时使用确定性离线客户端，契约与真实模型完全一致 | 保证测试可复现（文档 8.4.8） |
| 10 | YAML 为 Catalog 权威来源，`catalog_*` 表仅作补充（字段不足以承载完整契约） | 文档 6.8 实施顺序第 1/6 步 |

## 4. 与设计文档的已知差异

1. **`unsafe_request` 错误类型**：文档只在抽取失败示例中给出 `extraction_error`，未定义破坏性请求的错误类型；
   实现新增 `unsafe_request`（`recovery_strategy="abort"`），以满足 N01“直接拒绝”。
2. **`failed` 节点的兜底逻辑**：文档流程图有 `failed` 节点但未定义其行为；实现为“保证 `status="failed"` 且必带
   结构化 `error`”，不覆盖其它字段。
3. **AST 作用域**：字段校验使用语句级别名映射（CTE 输出列单独解析），不做完整作用域树；未识别字段一律拒绝，
   属于“更严格”而非“更宽松”的差异。
4. **`EXPLAIN` 兼容**：sqlglot 30 把 `EXPLAIN` 解析为 `Describe` 节点，校验器按节点名做版本兼容，
   `SQL_ALLOW_EXPLAIN=False` 时仍然拒绝。
5. **增量能力未实现（V1 范围外）**：SQL 置信度、human-in-loop、向量检索、`retry_with_new_table` 路由均按文档
   保留枚举但不在 V1 产生。

## 5. 运行环境说明

* 解释器：`.venv`（Python 3.11），依赖见 `pyproject.toml`；
* 数据库：MySQL 8.0.37，库 `ecommerce_text2sql`，只读账号 `text2sql_readonly`（仅 6 张视图 SELECT）；
* 模型：DeepSeek `deepseek-chat`（OpenAI 兼容端点），密钥只存在于本地 `.env`（已被 `.gitignore` 忽略）；
* 本机 DSH 沙箱对 `tempfile.mkdtemp` 与 `mode=0700` 目录有写入限制，因此 `scripts/sandbox_site/` 提供
  `sitecustomize` 兼容 shim，`scripts/dev.ps1` 会自动设置（普通 PowerShell 环境无需该 shim）。

## 6. 建议的后续工作

1. 全量数据（`data/raw`）导入后重跑验收报告，形成 sample/full 双基线；
2. Catalog 迁移到 MySQL（补齐 `role`/`aggregation`/`allowed`/join 规则字段）并按文档 6.8 第 6 步切换权威来源；
3. 增加 SQL 置信度与人工确认（V2）；
4. 明细层开放时的重复聚合风险规则与 `1:N` JOIN 支持；
5. 观测指标：节点耗时、Catalog 命中率、重试率、拒绝原因分布。
